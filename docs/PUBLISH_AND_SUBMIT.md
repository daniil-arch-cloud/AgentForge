# Как опубликовать AgentForge и приложить к заявке

## 1. Проверка перед публикацией

В PyCharm открой проект и выполни локальные тесты:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -p "test_*.py" -v
```

Убедись, что в папке лежит `.env` с настоящим ключом, а не `.env.example` (пример). **Никогда не загружай `.env`, `.venv`, `.idea` или личные токены.** Перед `git add` проверь список файлов.

## 2. Создать репозиторий

1. В GitHub нажми **New repository**.
2. Название: **AgentForge**; описание: **Prompt evolution and tool-trace evaluation for LLM agents**.
3. Выбери **Public**. README и `.gitignore` на сайте не создавай: они уже есть в проекте.
4. Создай пустой репозиторий.

## 3. Выложить проект из PyCharm Terminal

Перейди в директорию `AgentForge`, где лежит `README.md`, и выполни:

```powershell
git init
git branch -M main
git add .
git status
git commit -m "Initial AgentForge research prototype"
git remote add origin <URL_СОЗДАННОГО_РЕПОЗИТОРИЯ>
git push -u origin main
```

**Перед командой `git remote add`** замени `<URL_СОЗДАННОГО_РЕПОЗИТОРИЯ>` на HTTPS URL, который GitHub покажет на странице созданного репозитория. Не запускай команду с угловыми скобками буквально. Если `git push` требует входа, авторизуйся через браузер/JetBrains GitHub, а не вставляй токен в переписку.

Перед коммитом убедись по `git status`, что `.env` не отслеживается. Если он виден, остановись и исправь `.gitignore`.

## 4. Финальный прогон, когда API доступен

```powershell
.\.venv\Scripts\python.exe preflight.py
.\.venv\Scripts\python.exe main.py
```

Если `preflight.py` вернул ошибку, **не запускай полный эксперимент**. При наличии JSON:

```powershell
.\.venv\Scripts\python.exe make_report.py results\experiment_YYYYMMDD_HHMMSS.json
```

Сохрани новый JSON и отчет, внимательно проверь числа, затем добавь их отдельным коммитом. Не заменяй исторические показатели новым экспериментом до получения и проверки реальных результатов.

## 5. Заявка AIST

В комплекте вне репозитория подготовлены два DOCX: резюме и мотивационное письмо. В них указан профиль AgentForge как самостоятельного исследовательского прототипа, без преувеличений результатов. **После публикации** добавь настоящую ссылку на новый репозиторий в резюме и письмо, если нужно; не отправляй неверный или несуществующий URL.

Рекомендуемое краткое описание проекта для формы:

> AgentForge — Python-прототип автоматической эволюции системных инструкций LLM-агента с вызовом инструментов. Реализовал агент на Gemini API, три Python-инструмента, проверку конечного ответа и аргументов вызовов, автоматическое предложение и отбор инструкций на TRAIN и независимую проверку на HOLDOUT. На небольшом эксперименте получено улучшение на TRAIN, без улучшения на HOLDOUT; результаты и ограничения задокументированы. Интересуюсь исследованием методов автоматической разработки, проверки и адаптации агентных систем.
